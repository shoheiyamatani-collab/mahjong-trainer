# MリーグのCloudflare Pages分離

同じリポジトリのまま、Mリーグを別のPagesプロジェクトで公開できます。
成績更新ワークフロー、記事、データは移し替えずに維持します。

1. Cloudflare Pagesに別プロジェクトを作成します。仮のプロジェクト名は `jongfolio-mleague` です。実際に割り当てられたホスト名を使用します。
2. リポジトリルートをビルドルートとし、ビルドコマンドを `pnpm build:mleague:pages`、出力先を `apps/mleague/pages-out` に設定します。環境変数 `MLEAGUE_STANDALONE_URL` は新プロジェクトの本番オリジン（例：`https://jongfolio-mleague.pages.dev`）に設定します。プレビューでも同じ正規オリジンを用います。
3. 新サイトのトップ、対局日程、成績、選手・チーム詳細、画像、404、robots.txtを確認します。`/` は同一ホストの `/mleague/` に転送します。
4. 新サイト確認後にのみ、既存の雀フォリオPagesプロジェクトにも同じ `MLEAGUE_STANDALONE_URL` を設定し、従来の `pnpm build` で再デプロイします。Mリーグは本体の出力に含めず、旧パスを対応する新URLへ301転送します。旧動画案内は新サイトの切り抜き一覧へ転送します。
5. 本体トップ、代表ツール、旧URLの301と転送後の200を確認します。既存ドメイン全体は移転しないため、Search Consoleのアドレス変更は行いません。

新サイトにAdSense確認タグ・広告タグ・ads.txtは同梱しません。
新サイトにも既存のMリーグのインデックス方針を引き継ぎます。
本体の環境変数を削除して再ビルドすると、従来の統合構成へ戻せます。
